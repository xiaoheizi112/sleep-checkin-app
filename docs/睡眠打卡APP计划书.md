# 睡眠打卡 APP 产品计划书（自用版）

> 版本：v1.5 ｜ 日期：2026-10-29 ｜ 定位：个人自用开发蓝图（v1.5 记录睡眠质量测评完成）
>
> 实现状态：M1、M2 均已按计划完成；M2 后按实际使用反馈增补自动主题、双时间可编辑、睡眠质量测评，当前版本 v0.4.0。

---

## 1. 产品概述

### 1.1 一句话定位

一款只装在自己安卓手机上的私人睡眠打卡工具：睡前/起床一键打卡，顺手记一句梦，用报表和徽章帮自己坚持规律作息。

### 1.2 要解决的问题

- 熬夜无感知：没有记录，就不知道自己实际几点睡、睡了多久、作息漂移了多少。
- 坚持不下去：单纯"早睡"是个模糊愿望，缺少可视化的反馈和正激励，容易三天打鱼两天晒网。
- 市面 App 太重：主流睡眠 App 侧重传感器监测、内容社区、会员付费，功能繁杂，而自用只需要"记录 + 看见 + 坚持 + 留梦"四件事。

### 1.3 设计原则

| 原则 | 含义 |
|------|------|
| 10 秒完成打卡 | 睡前和起床各一次点击即可完成，评分和备注都是可选项，绝不设置流程障碍 |
| 打开即见数据 | 首页直接展示昨晚睡眠、连续天数和本周概况，不需要翻页找报表 |
| 零外部依赖 | 无账号、无登录、无后端、无网络请求，数据全部存手机本地，隐私绝对安全 |
| 宁精不宁多 | 只做三大模块内的功能，梦境仅作为打卡时的选填小记，其余一律进"不做清单" |

### 1.4 成功标准

- 自己在真机上连续使用 4 周以上，日均打卡操作时间 < 10 秒。
- 每周能生成一份可信的睡眠周报，连续打卡天数稳步上升。

## 2. 功能设计

功能分为三大模块：**打卡与记录**、**统计报表**、**习惯激励**（梦境记录不单独成模块，只作为起床打卡时的选填小记）。优先级定义：P0 = MVP 必须有，P1 = 第二阶段完成。

### 2.1 模块一：打卡与记录

| 编号 | 功能 | 优先级 | 说明 |
|------|------|--------|------|
| F1-1 | 睡前打卡 | P0 | 首页大按钮"我要睡了"，点击即记录当前时间为入睡时间；打卡后按钮变为已打卡状态 |
| F1-2 | 起床打卡 | P0 | 首页大按钮"我醒了"，点击记录起床时间，自动计算本次睡眠时长，并弹出可选的评分/备注浮层 |
| F1-3 | 睡眠质量评分 | P0 | 起床打卡后 1~5 星主观评分，可跳过（默认 3 星），用于统计"平均质量" |
| F1-4 | 备注 | P1 | 起床时可写一句话备注（如"喝咖啡了""运动了"），纯文本，可跳过 |
| F1-5 | 补卡 | P0 | 忘记打卡时，可在日历页选日期手动补录入睡/起床时间，补录数据标记为"手动"，与自动打卡区分 |
| F1-6 | 打卡修正 | P0 | 任意一条记录可编辑时间和评分，也可删除 |
| F1-7 | 跨天处理 | P0 | 睡前打卡时间落在 18:00~次日 12:00 区间内均视为"当晚入睡"，归属到起床那一天的记录（睡眠记录的锚点是起床日期），避免跨零点归属混乱 |
| F1-8 | 梦境小记（可选） | P0 | 起床打卡浮层中一个单行输入框，随手记一句梦，可一键跳过；随当天记录保存，在日历当日详情中显示 |

**核心打卡流程（文字版）：**

```
睡前：打开 App → 点"我要睡了" → 首页显示"已打卡 23:10，晚安" → 完成（3 秒）
起床：打开 App → 点"我醒了" → 显示"本次睡眠 7 小时 25 分" → 评星（可跳过）→ 顺手记一句梦（可跳过）→ 完成（5~30 秒）
异常：漏打卡 → 日历页选中该日 → 补录入睡/起床时间 → 记录标记为"手动"
```

### 2.2 模块二：统计报表

| 编号 | 功能 | 优先级 | 说明 |
|------|------|--------|------|
| F2-1 | 日历视图 | P0 | 按月展示日历，每天一个色块：绿色=正常打卡且达标，黄色=打卡但时长不足，灰色=未打卡，色块带角标区分"手动补录" |
| F2-2 | 首页概览卡 | P0 | 昨晚睡眠时长、本周平均时长、连续打卡天数，三个数字打开即见 |
| F2-3 | 周/月趋势图 | P1 | 折线/柱状图展示每日睡眠时长与入睡时间双轴趋势，支持周、月两个粒度切换 |
| F2-4 | 关键统计指标 | P1 | 平均入睡时间、平均起床时间、平均睡眠时长、平均质量评分、打卡完成率（打卡天数/总天数） |
| F2-5 | 作息规律性评分 | P1 | 0~100 分，衡量入睡/起床时间的波动程度：以近 14 天入睡时间与起床时间各自的标准差折算，波动越小分越高，首页展示 |
| F2-6 | 周报摘要 | P1 | 每周日生成一段文字摘要（本周平均时长、比上周变化、规律性评分、最好/最差一晚），存本地可回看 |
| F2-7 | 睡眠质量测评 | P1 | 近 14 天综合评分 0~100（时长 30%、作息规律 25%、入睡时间 20%、主观质量 15%、记录完整 10%），给出评级、逐项得分、问题分析与 3~5 条可执行建议；纯本地规则计算，满 5 条记录后生成，附"非医疗建议"声明 |

### 2.3 模块三：习惯激励体系

| 编号 | 功能 | 优先级 | 说明 |
|------|------|--------|------|
| F3-1 | 连续打卡天数 | P0 | 完成"睡前+起床"一对打卡记为 1 个有效打卡日；连续天数在首页醒目展示，断签自动清零（补卡可恢复连续性） |
| F3-2 | 里程碑徽章 | P1 | 达成连续 3/7/21/66/100 天等里程碑时解锁对应徽章，解锁瞬间全屏庆祝动效 + 本地通知（清单见附录 A） |
| F3-3 | 徽章墙 | P1 | 独立页面展示已点亮/未点亮徽章，未点亮的显示达成条件，制造收集欲 |
| F3-4 | 每周早睡目标 | P1 | 设定目标入睡时间（如 23:30）和每周达标天数（如 5 天）；一周内入睡时间早于目标的次数达标，点亮"本周早睡之星"标记 |
| F3-5 | 历史最长纪录 | P0 | 记录并展示"历史最长连续天数"，断签后仍有追赶目标 |

### 2.4 明确不做清单

以下功能明确排除在本项目外，避免范围蔓延：

- ❌ 助眠音频/白噪音/呼吸训练 —— 需要时用手机现成 App
- ❌ 提醒闹钟/睡前通知 —— 用手机系统闹钟，App 不做定时提醒（仅徽章解锁时发一条即时本地通知）
- ❌ 传感器自动监测睡眠 —— 不做手环/麦克风/加速度计监测，坚持主观打卡
- ❌ 梦境分类/梦境统计/AI 解梦/独立梦境页 —— 梦境只做起床时的一句话随手记
- ❌ 社交、好友、排行榜 —— 自用无需社交压力
- ❌ 云同步、账号登录 —— 数据只存本地，用导出 JSON 文件代替云备份
- ❌ iOS 版本 —— 只打包安卓 APK

## 3. 技术方案

### 3.1 选型总览

| 层 | 选型 | 理由 |
|----|------|------|
| 跨端框架 | **Flutter 3.x（Dart）** | 只需安卓一端；本机 `flutter build apk` 直接出安装包，不依赖云打包服务和任何账号；性能与 UI 一致性对图表和动效友好 |
| 状态管理 | Riverpod | 轻量、可测试，社区主流 |
| 本地数据库 | drift（SQLite 封装） | 类型安全、支持响应式查询（数据变更自动刷新 UI），纯本地无需服务器 |
| 图表 | fl_chart | Flutter 生态最成熟的图表库，满足折线/柱状需求 |
| 日历 | table_calendar | 支持自定义日格 widget，可做色块日历 |
| 本地通知 | flutter_local_notifications | 仅用于徽章解锁即时通知，无定时任务 |
| 数据导出 | share_plus + path_provider | 导出 JSON 到手机存储，防数据丢失 |

### 3.2 系统架构

```
┌─────────────────────────────────────┐
│              UI 层（页面）             │
│  首页打卡 │ 日历 │ 统计 │ 徽章墙 │ 设置  │
├─────────────────────────────────────┤
│         状态层（Riverpod Provider）    │
│  打卡状态 │ 统计数据 │ 连续天数 │ 徽章   │
├─────────────────────────────────────┤
│            业务逻辑层（Service）        │
│  SleepRecordService 打卡/补卡/修正      │
│  StatsService       指标计算/规律性评分  │
│  StreakService      连续天数/里程碑判定  │
├─────────────────────────────────────┤
│            数据层（drift/SQLite）      │
│  sleep_records │ badges │ settings     │
└─────────────────────────────────────┘
      （无网络层 —— 完全离线单机应用）
```

### 3.3 核心数据模型

**表 1：sleep_records（睡眠记录表）—— 核心表**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 自增主键 |
| anchor_date | TEXT (ISO date) | 记录归属日期（=起床日，见 F1-7 跨天规则） |
| bed_time | TEXT (ISO datetime) | 入睡打卡时间 |
| wake_time | TEXT (ISO datetime) | 起床打卡时间 |
| duration_min | INTEGER | 睡眠时长（分钟），由 wake - bed 计算冗余存储，便于统计 |
| quality | INTEGER | 主观评分 1~5，默认 3 |
| note | TEXT NULL | 备注，可空 |
| dream | TEXT NULL | 梦境小记，起床打卡时可选填一句话，可空 |
| is_manual | INTEGER (0/1) | 是否手动补录 |
| status | TEXT | `bed_only`（只打了睡前卡）/ `complete`（一对完整打卡） |
| created_at / updated_at | TEXT | 创建/修改时间 |

约束：`anchor_date` 唯一（一天最多一条睡眠记录）；`status=bed_only` 时 wake 相关字段为空。

**表 2：badges（徽章表）**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 自增主键 |
| badge_key | TEXT UNIQUE | 徽章标识，如 `streak_7`、`early_week`（清单见附录 A） |
| unlocked_at | TEXT NULL | 解锁时间，NULL = 未解锁 |

**表 3：settings（设置表，key-value 结构）**

| 字段 | 说明 |
|------|------|
| key / value | 存储：每周早睡目标时间（默认 23:30）、每周达标天数（默认 5）、时长达标线（默认 7 小时，用于日历绿色/黄色判定）、历史最长连续天数 |

> 说明：连续天数不落库为字段，每次由 sleep_records 实时计算（自用数据量小，万条以内实时计算毫秒级），避免状态不同步；历史最长纪录作为 settings 持久化。

### 3.4 关键逻辑说明

- **连续天数计算**：取所有 `status=complete` 的记录按 anchor_date 排序，从今天（或昨天，若今天尚未完成）向前逐日回溯连续段。
- **规律性评分**：取近 14 天完整记录，分别计算入睡时刻（跨零点的按 +24h 处理）与起床时刻的标准差 σ（单位：分钟）；评分 = max(0, 100 − (σ_bed + σ_wake) × 0.25)，即两项波动合计每增加 4 分钟扣 1 分（例：入睡波动 30 分钟 + 起床波动 20 分钟 → 87.5 分）。
- **打卡防误触**：睡前打卡后 5 分钟内可撤销；重复点击不产生新记录，仅提示当前状态。
- **数据备份**：设置页"导出 JSON"将三张表完整导出到 `Download/sleep_checkin_backup_日期.json`；换机或重装后通过"导入 JSON"恢复。

## 4. 开发排期

自用项目按业余时间推进，划分为两个里程碑，每个里程碑结束都产出可安装的 APK。

### M1 —— 核心可用（预计 1~2 周业余时间）

**范围**：Flutter 工程搭建 → drift 数据层 → 首页睡前/起床打卡（F1-1/2/3/7/8，含可选的一句梦）→ 日历视图与补卡（F2-1、F1-5/6）→ 首页概览卡（F2-2）→ 连续天数（F3-1/5）→ 打包 APK 装机试用。

**验收标准**：
1. 真机上完成一次完整的"睡前打卡→起床打卡→评星"流程，操作 ≤ 10 秒。
2. 跨零点打卡（23:50 睡、7:10 起）归属日期正确、时长计算正确。
3. 日历色块与补卡功能可用，补录记录带"手动"标记。
4. 首页连续天数与实际打卡记录一致，断签清零、补卡恢复。
5. 起床打卡浮层可填一句梦（可跳过），并在日历当日详情中正确显示。

### M2 —— 完整体验（M1 后再 1~2 周）

**范围**：备注功能（F1-4）→ 周/月趋势图与关键指标（F2-3/4）→ 规律性评分（F2-5）→ 周报摘要（F2-6）→ 里程碑徽章 + 解锁动效与通知（F3-2）→ 徽章墙（F3-3）→ 每周早睡目标（F3-4）→ JSON 导出/导入 → 整体 UI 打磨（深色模式为默认，睡前场景友好）。

**验收标准**：
1. 统计页周/月切换流畅，指标与手工核算一致。
2. 模拟达成连续 7 天，徽章解锁动效与通知正常触发，徽章墙状态正确。
3. 导出 JSON → 卸载重装 → 导入 JSON，数据完整恢复。
4. 全部功能默认深色主题下无显示问题。

## 5. 安装与日常使用

### 5.1 环境准备（一次性）

1. Windows 上安装 Flutter SDK 与 Android SDK（Android Studio 自带），`flutter doctor` 全绿。
2. 手机开启"开发者选项 → 允许安装未知来源应用"。

### 5.2 打包与安装

```bash
flutter build apk --release
# 产物：build/app/outputs/flutter-apk/app-release.apk
```

APK 传到手机（数据线 / 微信文件传输 / 本地局域网均可）点击安装。后续每次迭代重新打包覆盖安装即可，**覆盖安装不清除本地数据**（drift 数据库随 App 沙箱保留）。

### 5.3 日常使用与备份建议

- 睡前、起床后各打开一次 App 打卡，全程 < 10 秒。
- 起床打卡时顺手记一句梦（可选）：梦境在醒来 5 分钟内最清晰。
- 每月导出一次 JSON 备份（设置页一键操作），存到手机网盘或电脑；换机、刷机前先导出。
- App 不做任何提醒，睡前/起床提醒请配合手机系统闹钟（如 23:15 就寝提醒、7:00 起床闹钟）。

```
│     ├── 顶部：问候语 + 当前时间

│     ├── 概览卡：昨晚时长 │ 本周平均 │ 连续 N 天（含历史最长）
│     └── 本周早睡进度条（M2）
├── ② 统计
│     ├── 日历视图（色块月历，点选日期→当日详情/补卡入口）
│     ├── 趋势图（周/月切换，时长柱状 + 入睡时间折线）
│     ├── 指标卡：平均入睡/起床/时长/质量/完成率/规律性评分
│     └── 周报列表（M2）
└── ③ 我的
      ├── 徽章墙（已点亮/未点亮）
      ├── 目标设置（早睡时间、每周达标天数、时长达标线）
      ├── 数据导出/导入 JSON
      └── 关于（版本号）
```

### B.2 关键页面原型（文字版）

**首页·睡前状态**：深色背景，中央一枚大圆按钮"我要睡了 🌙"，下方小字"上次睡眠：7 小时 25 分"。点击后按钮变为灰紫色"已打卡 23:10 · 晚安"，并显示"明早点『我醒了』完成记录"。

**首页·起床状态**：中央按钮变为"我醒了 ☀️"，点击后弹出底部浮层：大字显示"本次睡眠 7 小时 25 分"，下方 5 颗星评分（默认选中 3 星）+ 一行"记一句梦（可选）"输入框 + 备注输入框（M2）+ "完成"按钮，浮层可整体下滑跳过。

**统计·日历页**：月历每格右上角小圆点表示状态（绿/黄/灰），手动补录的日期格子左上角加"✎"角标；点选日期展开当日卡片（入睡、起床、时长、评分、备注、梦境），卡片右上"编辑"进入修正。

**我的·徽章墙**：3 列网格，已解锁徽章彩色 + 解锁日期，未解锁灰度 + 条件文案（如"连续打卡 66 天 6/66"进度提示）。

### B.3 数据埋点建议（自用简化版）

无需第三方统计。仅在本地记录两类事件用于自我观察：每日打卡完成时刻（评估自己"打卡动作"是否发生在合理时间窗）、每周导出备份是否执行。后续如需分析，直接从导出的 JSON 中处理。

## 附录 C：视觉风格规范（v1）

### C.1 风格定位

**深夜静谧 · 低刺激**：深色为主、低饱和、暖色点缀；睡前看不刺眼，晨起看得清。不做插画和复杂装饰，每屏视觉重心只有一个（大打卡按钮或关键数字）。

关键词：静谧 / 克制 / 温暖 / 大数字。

### C.2 色彩方案（深色 + 日间浅色）

| 用途 | 色值 | 说明 |
|------|------|------|
| 页面背景 | `#0E1318` | 近黑的深墨蓝，比纯黑柔和 |
| 卡片/浮层 | `#1A2128` | 比背景亮一级 |
| 主文字 | `#ECE8E1` | 暖白，深夜不刺眼 |
| 次文字/说明 | `#8A929B` | 灰蓝 |
| 睡前态主色 | `#E8C07A` 月光金 | 睡眠按钮、强调、选中态 |
| 起床态主色 | `#F2A65A` 晨光橙 | 起床按钮与睡眠时长数字 |
| 达标绿 | `#7FA98C` 灰豆绿 | 日历达标色块 |
| 未达标黄 | `#C9A15E` 陈金 | 日历时长不足色块 |
| 未打卡灰 | `#39424B` | 日历空白天、禁用态 |
| 危险红 | `#C96F6F` | 仅删除确认等破坏性操作 |

日间浅色（7:00–19:00 自动启用）：背景 `#F4EFE6` 暖纸色，卡片 `#FFFCF6`，主文字 `#2A251F`，次文字 `#726A5F`，强调色 `#B5813C` 古铜金 / `#C1753A` 暖橙，达标绿 `#4F7A5C`，未达标黄 `#8F6420`，未打卡灰 `#DCD3C4`。浅色主题不使用纯白，保持同一套温暖克制的观感。

三条硬规则：

1. 不用纯黑 `#000000` 与纯白 `#FFFFFF`——深夜刺眼，纯黑底在 OLED 上做动画易拖影；
2. 主色不用蓝——蓝光偏冷、屏幕感重，用"月光金（睡前）→ 晨光橙（起床）"区分两个打卡状态；
3. 同一页面只出现一个强调色，状态色只用于日历与图表，不进入主界面。

### C.3 字体与文字层级

- 使用系统默认字体（Android 自带 Roboto/Noto Sans SC，国产 ROM 自动回退厂商字体），不引入第三方字体：安装包小、渲染稳定、无授权问题。
- 数字一律用等宽数字（tabular figures），时长、连续天数等大数字 48~56sp 加粗，是页面的视觉主角。
- 层级：大数字 48~56sp / 页面标题 20sp / 正文 15sp / 辅助说明 12sp；不用斜体与全大写英文。

### C.4 形状、间距与图标

- 卡片圆角 16dp，底部浮层顶部圆角 24dp，打卡按钮为正圆（直径约 200dp）。
- 8dp 栅格：页边距 16dp，模块间距 24dp，卡片内边距 16dp。
- 图标统一用 Material Symbols Rounded 线性风格（1.5px 描边），只出现在导航与功能性位置；装饰图形至多一个（打卡按钮内的小弯月/太阳）。

### C.5 动效

- 打卡状态切换：按钮颜色渐变 + 轻微缩放（200ms ease-out），配一行"已打卡"小字。
- 页面切换用系统默认过渡（Fade through），不做自定义转场。
- 只有徽章解锁（M2）做庆祝动效，其余一律克制。

### C.6 日间/夜间使用细节

- 主题按时间自动切换：7:00–19:00 浅色，其余时间深色；跨过时间点自动渐变，无需手动设置。
- 首页右上角与底部导航的打卡图标：白天太阳、夜间月亮。
- Splash 与页面背景同色，避免启动白屏闪光。
- 状态栏透明、图标颜色随主题变化；系统导航栏与页面背景同色。
- 主打卡按钮放在屏幕下半部拇指可及区，单手操作无需够顶部。

### C.7 应用图标与启动页

- 应用图标：深墨蓝底 + 暖金色弯月，无文字；使用 Android adaptive icon，月亮居中放在安全区内。
- 启动页：同色背景 + 中央小弯月，1 秒内进入首页。

### C.8 Flutter 落地方式

所有色值集中为两套 `AppPalette`（深色/浅色），通过 Material 3 的 `ThemeExtension` 挂载，页面里统一用 `context.appColors` 取色，禁止硬编码颜色。`MaterialApp` 同时提供 `theme`（浅色）、`darkTheme`（深色）和 `themeMode`：

```dart
// lib/theme/app_colors.dart
class AppPalette extends ThemeExtension<AppPalette> { /* bg/surface/... */ }
const darkPalette = AppPalette(brightness: Brightness.dark, bg: Color(0xFF0E1318), /* ... */);
const lightPalette = AppPalette(brightness: Brightness.light, bg: Color(0xFFF4EFE6), /* ... */);

extension AppPaletteContext on BuildContext {
  AppPalette get appColors => Theme.of(this).extension<AppPalette>()!;
}

// lib/theme/app_theme.dart
ThemeData buildDarkTheme() => _buildTheme(darkPalette);
ThemeData buildLightTheme() => _buildTheme(lightPalette);

// lib/main.dart：7:00–19:00 浅色，其余深色
MaterialApp(
  theme: buildLightTheme(),
  darkTheme: buildDarkTheme(),
  themeMode: ref.watch(themeModeProvider),
  // ...
);
```
